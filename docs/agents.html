A skill that sets it up and uses it.

skills/keydrop-setup/SKILL.md is written for any coding agent in any harness. Its rule: never ask the user to paste a secret into the conversation, and never echo one into it.

Read SKILL.md →
01 · What the skill does

Take stock, choose, prove, then ask.

It walks the agent through taking stock of the machine, choosing a vault and transport, getting a conforming implementation in place (the reference where it fits, adapters built to the spec where it doesn't), proving conformance, and then asking for secrets through a link.

Some steps are left to the human on purpose: confirming the owner's login, turning on Serve and HTTPS certificates, answering unlock prompts, choosing policy, and loading an always-on service. The skill says so and waits.

What an agent runs when a task needs a key it doesn't have.

# already there?
keydrop list

# no: ask for it, send the user the link
keydrop request openai-api-key --note "for the summariser in ~/proj"

# wait for the name to drop out of
keydrop status

# use it without printing it
OPENAI_API_KEY="$(keydrop get openai-api-key)" some-command
