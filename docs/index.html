Give an agent a secret without pasting it into the chat.

A local tool asks for a key by name. keydrop prints a one-shot link on your tailnet. You open it on a device signed in to your tailnet, paste the value, and it goes straight into the login keychain. The page shuts itself down, and the tool reads the value back by name.

Source on GitHub Read the spec
In use

One command on your side. One field on theirs.

The requester never sees the value until it asks for it by name. You never type it anywhere a transcript, a shell history or a config file would keep it.

$ keydrop request openai-api-key --note "for the summariser"
https://your-mac.example.ts.net:61234/3vQx...

# Open the link on any device signed in to your tailnet.
# Paste the key, tap Store. The page answers
# "Stored. You can close this." and shuts down.

$ keydrop status
# ... once openai-api-key is no longer pending:

$ OPENAI_API_KEY="$(keydrop get openai-api-key)" some-command

The link stops working after one good submit, after the TTL (15 minutes by default, an hour at most), after five bad requests, or on keydrop cancel openai-api-key. keydrop get prints no trailing newline when stdout isn't a terminal, so command substitution is clean.

The whole page. No script, no cookies, no stylesheet fetched from anywhere, and the input asks browsers and password managers not to save what you type.

01 · How it works

One path for the value, checked on every request.

Four parties on your Mac and one browser. The brass line is the only route the value ever takes.

the value everything else any channel you like
  1. Request. Your tool runs keydrop request <name>. keydrop checks the name, binds a listener on 127.0.0.1, asks tailscale serve for an HTTPS route to it on the same port number, confirms the route exists, and only then accepts connections.
  2. Link. It prints the link once and detaches. The path carries a 256-bit token from a cryptographically secure generator.
  3. Deliver. The link reaches you over whatever channel the tool already has. A chat message is fine: to anyone the tailnet won't authenticate as you, the link is useless.
  4. Submit. You open it on a device signed in to your tailnet and submit the value. Every request is checked in this order: the route is still keydrop's own, the Host is on the allowlist, Tailscale-User-Login is the owner, the token matches in constant time. Anything else gets a bare 404.
  5. Store and verify. keydrop hands the value to security -i on stdin as hex, reads it back, and compares digests. Only a match counts as stored.
  6. Close. The page says "Stored. You can close this." keydrop closes the route, confirms with Tailscale that it's gone, and exits.
  7. Read back. Your tool runs keydrop get <name> and passes the value on without printing it.

A request also ends on the TTL, after five bad requests, on keydrop cancel, and on any signal or crash. Every one of those paths closes the route. Routes left by a killed process are found and removed later, and only routes keydrop itself created are ever removed.

02 · Two more pages

A vault page and a home page. Both write-only.

Same token in the path, same owner check, same route check on every request, same teardown. Neither ever renders a stored value, so a screenshot, a browser cache or someone over your shoulder gets nothing.

keydrop vault

A session link, held open for one TTL. The page lists names, notes and times, and lets you add, replace and delete entries under the service prefix. Every post needs the session's form token as well as the path token. Delete asks first. The Done button ends the link.

keydrop home

The vault page with no TTL, meant to stay up under launchd. In place of the TTL it has a lockout that survives restarts, a write rate limit, an audit log and a stop switch. Only bad requests carrying your login and same-origin Fetch Metadata count as strikes, so a stranger or a cross-site page can't lock you out.

The kill switch

keydrop home --stop takes the route down and leaves a flag that keeps it down. It reports success only once serve status shows nothing on the home port still pointing at the page. Five bad requests in 24 hours lock it the same way. keydrop home --unlock brings it back; --new-link replaces the link without a restart.

Notes from the vault page are stored in plain text in the state dir, so don't put secrets in them.

03 · Threat model

What it defends against, and what it doesn't.

keydrop protects the way into the keychain. It does not protect the keychain from software already running as you. The reasoning behind each check is in the docstring at the top of the script; the invariants every implementation keeps are in section 4 of the spec.

Defends against

  • The value reaching a chat, a log or argv. It goes from the browser to keydrop, then to security -i on stdin as hex. Logs hold only name, time and outcome. Every write is read back before the page says Stored.
  • Other people on your tailnet. Every request needs the owner's Tailscale-User-Login, which tailscale serve sets from the connection and peers can't forge. Lookalike spellings of that header are refused.
  • Guessing the link. The token is 256 bits, compared in constant time. On a one-shot or vault link, five bad requests end it early. On the home page only a wrong token sent with your login counts, and five in 24 hours lock it until keydrop home --unlock.
  • Browsers on the Mac. An exact Host allowlist stops DNS rebinding. Form tokens and Fetch Metadata stop cross-site posts, and a cross-site request can't run up strikes on the home page.
  • A loopback port left open to the tailnet. Under userspace networking, tailscaled forwards tailnet traffic to 127.0.0.1 on the same port when serve doesn't claim it. keydrop uses the same port on both sides, listens only after the route exists, and checks on every request that the route is still its own, exiting if not.
  • Leftover routes. Teardown on every exit path and a reap for killed processes. keydrop keeps a ledger of every serve route it creates and only sweeps ledger entries no live record owns, and only while the route still points where keydrop pointed it. A route keydrop didn't create is never removed.
  • Funnel. If Funnel gets turned on for a page's port, the page treats its route as gone: it answers a bare 404 and exits.
  • Reading values through a page. The vault and home pages are write-only.

Doesn't defend against

  • Anything running as you on the Mac. It can run keydrop get or security itself. keydrop protects the way into the keychain, not the keychain.
  • Local processes connecting to 127.0.0.1. They can send any header. They still need the token.
  • A compromised device signed in as you, or anyone holding the link. Treat a link like a short-lived password.
  • A compromised tailscaled, or a tailnet admin.
  • Untested setups. The port analysis was worked out against tailscaled with userspace networking. A kernel-TUN tailscaled, such as the macOS app, hasn't been analysed.
04 · The spec

Written so keydrop can be rebuilt anywhere.

SPEC.md fixes what any keydrop must do: the flow, the item types, the page and its exact wording, the invariants, the vault and transport adapter interfaces, and the conformance checks. It's written so keydrop can be rebuilt on Linux or Windows, with 1Password, Bitwarden, pass, KeePassXC or another store, and with or without Tailscale. The Python script is the reference implementation, for macOS, the login keychain and tailscale serve. The spec is a draft, version 0.1.

Twelve invariants. None of them is configurable.

  1. I1
    One-shot link.Exactly one successful submission, then nothing.
  2. I2
    Bounded lifetime.15 minutes by default, an hour at most.
  3. I3
    Only the owner can submit.No owner configured, nothing starts.
  4. I4
    The token is necessary.256 bits, constant-time, a few bad requests end the page.
  5. I5
    The value never leaves browser, page, vault.Not argv, env, logs, responses, errors or the requester's output.
  6. I6
    Verified store.Stored means read back and matched, not exit status zero.
  7. I7
    The page shuts down.On store, TTL, lockout, cancel, signal or crash. Confirmed gone.
  8. I8
    Read-back by name only.No page, response or log ever renders a value.
  9. I9
    The route is checked on every request.Still ours, no wider than opened. Else 404 and exit.
  10. I10
    Strikes only from the owner.A stranger or a cross-site page can't lock you out.
  11. I11
    No public, unauthenticated exposure.No Funnel, no open tunnel, no 0.0.0.0, no plain HTTP.
  12. I12
    Policy is enforced before a link exists.A disabled type is refused at the command line.

An implementation that cannot meet one of these on a given machine must refuse to run there and say which one.

Vault adapter

Store, read, list and delete inside one namespace. A value reaches the store by stdin, an inherited file descriptor or an in-process API. A CLI that only takes the value as an argument can't be used.

capabilities() -> {native_types, write_channel,
                   lists_without_unlock, max_bytes}
store(name, item)  -> ok | error(reason)
get(name)          -> item | not_found | error
list()             -> [{name, type, created?, updated?}]
delete(name)       -> ok | not_found | error

Transport adapter

Makes the page reachable only by clients it authenticates, proves who is connecting, and tears the route down again. Acceptable: a tailnet identity header, an authenticated proxy with a verified identity, an SSH forward, or localhost by policy.

open(port)          -> url | error(reason)
identity(request)   -> login | none
still_ours(port)    -> yes | no | unknown
close(port)         -> confirmed | error(reason)
host_allowlist(port) -> [host]
ledger

Conformance

27 black-box checks, C-01 to C-27, written against the command interface and HTTP so they apply to any language. They run against a fake vault, a stub transport and a process watcher, never a real store or network. Then one real round trip with a throwaway name, and a report listing every check as pass, fail or not applicable.

Where the reference is behind the spec today

Section 12 of the spec keeps this list. As of now:

  • No item types. It has one field, value, with no --type, --fields, get --field or policy keys.
  • No adapter seam. The keychain and Tailscale calls are made directly, not behind the interfaces above.
  • No expired, cancelled or used screens, and no "Link ends HH:MM." line on the request form. A finished page is simply gone, which the spec allows.
  • A blank submit answers "Nothing was entered." as a message page instead of re-rendering the form.
  • Some copy says "keychain" and "on the Mac" where the spec says "vault" and "on this machine".
  • Exit codes don't follow section 6 exactly, and the test suites are white-box Python rather than the black-box checks.
05 · For agents

A skill that sets it up and uses it.

skills/keydrop-setup/SKILL.md is written for any coding agent in any harness. Its rule: never ask the user to paste a secret into the conversation, and never echo one into it. It walks the agent through taking stock of the machine, choosing a vault and transport, getting a conforming implementation in place (the reference where it fits, adapters built to the spec where it doesn't), proving conformance, and then asking for secrets through a link.

Some steps are left to the human on purpose: confirming the owner's login, turning on Serve and HTTPS certificates, answering unlock prompts, choosing policy, and loading an always-on service. The skill says so and waits.

What an agent runs when a task needs a key it doesn't have.

# already there?
keydrop list

# no: ask for it, send the user the link
keydrop request openai-api-key --note "for the summariser in ~/proj"

# wait for the name to drop out of
keydrop status

# use it without printing it
OPENAI_API_KEY="$(keydrop get openai-api-key)" some-command
Not shipped · in progress

What's coming.

A redesign is under way separately from the reference script. None of it is in the released code; what's described above is what runs today.

  • Typed, multi-field credentials. The spec already defines a credential type: username, password, and optional one-time code secret, website and notes, with the optional fields chosen per request. The reference has one field and no --type.
  • Fields that fit the service. A request for a given service showing the fields that service actually needs, rather than one generic form.
  • A proper key-management page, in place of the write-only list the vault page has today.
06 · Requirements and commands

Three requirements. Nine commands.

Requirements

  • macOS. The vault is the login keychain, driven through /usr/bin/security.
  • Tailscale, with tailscale serve available to your user and HTTPS certificates enabled for the tailnet. Without certificates every page refuses to start unless you pass --http, and the home page doesn't run at all.
  • python3, 3.9 or later. No other dependencies.

Configuration

Read from ~/.config/keydrop/config.json, or the file named by KEYDROP_CONFIG. Environment variables override the file. Only one key has no default.

{
  "owner_login": "you@example.com"
}

owner_login is your Tailscale login exactly as tailscale status shows it. keydrop never falls back to accepting any login. keydrop config prints the settings in effect.

keydrop request <name> [--note "…"] [--ttl 15m]
Prints a one-shot link and returns. The page runs in the background.
keydrop get <name>
Prints the stored value, for local tools. No trailing newline when stdout isn't a terminal.
keydrop list
Names only. Never values.
keydrop status
Pending requests and vault sessions.
keydrop cancel <name>
Ends a pending request. cancel vault ends a vault session.
keydrop vault [--ttl 15m]
A session link for listing, adding, replacing and deleting entries.
keydrop home
The always-on vault page, for launchd. HTTPS only.
keydrop home --new-link | --stop | --unlock
Mint a new link, take the page down and keep it down, or clear a stop or lockout.
keydrop config
The settings in effect. Never a value.

Names are lowercase letters, digits, ., _ and -, up to 64 characters. A key named openai-api-key is stored as a generic password with service keydrop.openai-api-key and account keydrop.
